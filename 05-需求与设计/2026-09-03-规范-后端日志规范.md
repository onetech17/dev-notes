# 后端日志规范

## 目标

- ✅ **精简有效**：避免日志冗余，每条日志都有明确价值
- ✅ **可追踪**：支持问题定位、链路追踪、故障排查
- ✅ **可观测**：关键路径、异常、性能瓶颈清晰可见
- ✅ **安全合规**：不打印敏感信息，符合审计要求

---

## 一、日志级别使用规范

### 📊 日志级别定义

| 级别 | 使用场景 | 示例 | AI是否默认输出 |
|------|----------|------|---------------|
| **ERROR** | 系统错误、异常、失败 | 数据库连接失败、接口返回5xx、关键业务逻辑异常 | ✅ **必须** |
| **WARN** | 可恢复的异常、降级、告警 | 重试成功、缓存未命中降级查库、参数校验失败 | ✅ **必须** |
| **INFO** | 关键业务事件、状态变更 | 用户登录成功、订单创建、支付完成、定时任务执行 | ⚠️ **选择性** |
| **DEBUG** | 调试信息、详细流程 | 方法入参出参、中间状态、分支选择 | ❌ **默认关闭** |
| **TRACE** | 最详细的追踪信息 | 每个函数入口出口、循环迭代、SQL执行细节 | ❌ **禁止** |

## 二、必须打印日志的关键点

### ✅ 强制日志点（ERROR/WARN级别）

#### 1. 异常与错误
```python
# ✅ 正确：捕获异常并记录上下文
try:
    result = await db.query(sql, params)
except DatabaseError as e:
    logger.error("数据库查询失败", extra={
        "sql": sql,
        "params": params,
        "error": str(e),
        "trace_id": request.trace_id
    })
    raise

# ❌ 错误：只打印异常不打印上下文
except Exception as e:
    logger.error(f"出错了: {e}")
```

#### 2. 外部调用失败
```python
# ✅ 正确：记录调用目标、参数、错误
response = await http.post(url, json=payload)
if response.status_code != 200:
    logger.error("第三方API调用失败", extra={
        "service": "payment-gateway",
        "url": url,
        "status": response.status_code,
        "body": payload,
        "trace_id": trace_id
    })
```

#### 3. 关键业务失败
```python
# ✅ 正确：记录业务标识、失败原因
if not order.create():
    logger.error("订单创建失败", extra={
        "user_id": user_id,
        "product_ids": product_ids,
        "amount": amount,
        "reason": "库存不足",
        "trace_id": trace_id
    })
```

#### 4. 重试与降级
```python
# ✅ 正确：记录重试次数、最终结果
for attempt in range(max_retries):
    try:
        return await call_service()
    except ServiceError as e:
        if attempt == max_retries - 1:
            logger.error("服务调用最终失败，启用降级", extra={
                "service": "recommendation",
                "attempts": max_retries,
                "last_error": str(e),
                "fallback": "返回空列表"
            })
            return []
        logger.warning("服务调用失败，准备重试", extra={
            "attempt": attempt + 1,
            "max_retries": max_retries,
            "error": str(e)
        })
```

### ⚠️ 选择性日志点（INFO级别）

#### 1. 关键业务事件（按模块配置）
```python
# ✅ 正确：记录业务事件的核心信息
logger.info("用户登录成功", extra={
    "user_id": user_id,
    "login_type": "password",  # password/sms/oauth
    "ip": client_ip
})

# ❌ 冗余：过于详细
logger.debug(f"用户{user_id}在{datetime.now()}使用密码方式从IP{client_ip}登录成功，session_id={session_id}")
```

#### 2. 接口入口/出口（仅慢接口或特定模块）
```python
# ✅ 正确：仅记录慢接口或关键接口
if duration > SLOW_THRESHOLD:
    logger.warning("接口响应缓慢", extra={
        "endpoint": request.path,
        "method": request.method,
        "duration_ms": duration,
        "trace_id": trace_id
    })

# ❌ 冗余：所有接口都打印
logger.info(f"进入{func.__name__}方法，参数{args}")
logger.info(f"离开{func.__name__}方法，返回{result}")
```

#### 3. 定时任务执行
```python
# ✅ 正确：记录任务执行结果
logger.info("定时任务执行完成", extra={
    "task_name": "daily_report",
    "status": "success",  # success/failed
    "processed_count": count,
    "duration_seconds": duration
})
```

---

### ❌ 禁止或限制的日志

#### 1. 禁止打印每个函数入口出口
```python
# ❌ 错误：日志爆炸，无实际价值
def process_order(order_id):
    logger.debug(f"进入process_order，order_id={order_id}")
    # ... 处理逻辑
    logger.debug(f"离开process_order，返回{result}")
    return result
```

#### 2. 禁止打印循环内部
```python
# ❌ 错误：数据量大时日志爆炸
for item in items:
    logger.debug(f"处理item: {item.id}")
    process(item)

# ✅ 正确：仅记录汇总
logger.info("批量处理完成", extra={
    "total": len(items),
    "success": success_count,
    "failed": failed_count
})
```

#### 3. 禁止打印正常流程的每一步
```python
# ❌ 错误：正常流程不需要每一步都记录
logger.debug("开始验证用户")
# ... 验证逻辑
logger.debug("用户验证通过")
logger.debug("开始检查库存")
# ... 库存检查
logger.debug("库存检查通过")

# ✅ 正确：只记录关键节点或异常
if not user.is_valid:
    logger.warning("用户验证失败", extra={"user_id": user_id, "reason": "账号已禁用"})
```

#### 4. 禁止打印敏感信息
```python
# ❌ 错误：泄露敏感信息
logger.debug(f"用户密码: {password}")
logger.debug(f"API Key: {api_key}")
logger.debug(f"身份证: {id_card}")

# ✅ 正确：脱敏或只打印部分
logger.info("用户认证", extra={
    "user_id": user_id,
    "auth_type": "password",
    "id_card_masked": id_card[:6] + "****" + id_card[-4:]
})
```

## 三、日志格式规范

### 📝 标准格式

```json
{
  "timestamp": "2026-09-03T09:30:00.123+08:00",
  "level": "ERROR",
  "logger": "app.services.order",
  "message": "订单创建失败",
  "trace_id": "abc123def456",
  "span_id": "span789",
  "service": "order-service",
  "extra": {
    "user_id": "u_12345",
    "order_id": "o_67890",
    "error": "库存不足",
    "error_code": "STOCK_INSUFFICIENT"
  }
}
```

### 🔗 链路追踪字段

**必须包含**：
- `trace_id`: 全链路唯一标识，从入口透传到所有子调用
- `span_id`: 当前操作标识
- `parent_span_id`: 父操作标识（可选）

**透传示例**：
```python
# 入口中间件
@app.middleware("http")
async def trace_middleware(request, call_next):
    trace_id = request.headers.get("X-Trace-Id") or str(uuid.uuid4())
    request.state.trace_id = trace_id
    
    # 设置全局上下文
    with log_context(trace_id=trace_id):
        response = await call_next(request)
    
    response.headers["X-Trace-Id"] = trace_id
    return response

# 业务代码自动获取trace_id
async def create_order(user_id, items):
    logger.info("创建订单", extra={
        "user_id": user_id,
        # trace_id自动从上下文获取
    })
```

## 四、AI日志生成规则

### 🤖 给AI的明确指令

在让AI生成代码时，使用以下指令控制日志输出：

```markdown

   - 所有异常（ERROR级别，包含错误原因、参数、trace_id）

   - 关键业务失败（订单创建失败、支付失败等）
```

## 五、日志配置建议

### 📋 生产环境配置

```yaml
# logging.yaml
version: 1
disable_existing_loggers: false

formatters:
  json:
    class: pythonjsonlogger.jsonlogger.JsonFormatter
    format: "%(asctime)s %(levelname)s %(name)s %(message)s %(trace_id)s %(span_id)s"

handlers:
  console:
    class: logging.StreamHandler
    level: INFO
    formatter: json
    stream: ext://sys.stdout

  file:
    class: logging.handlers.RotatingFileHandler
    level: DEBUG
    formatter: json
    filename: /var/log/app/app.log
    maxBytes: 104857600  # 100MB
    backupCount: 10

loggers:
  # 应用日志
  app:
    level: INFO
    handlers: [console, file]
    propagate: false

  # 第三方库日志降级
  urllib3:
    level: WARNING
    handlers: [console]
    propagate: false
  
  sqlalchemy:
    level: WARNING
    handlers: [console]
    propagate: false

# 根日志
root:
  level: WARNING
  handlers: [console]
```

### 🔍 调试模式配置

```yaml
# 开发/调试环境
loggers:
  app:
    level: DEBUG  # 开发时开启DEBUG
    handlers: [console]
```

## 六、日志检查清单

在代码审查或AI生成代码后，检查以下问题：

### ✅ 检查清单

- [ ] 所有异常捕获点都有ERROR日志
- [ ] 外部调用失败有ERROR/WARN日志
- [ ] 关键业务失败有ERROR日志
- [ ] 重试操作有WARN日志（记录重试次数）
- [ ] 日志包含trace_id用于链路追踪
- [ ] 错误日志包含足够的上下文（参数、错误原因）
- [ ] 没有打印每个函数的入口/出口
- [ ] 没有打印循环内部
- [ ] 没有打印敏感信息
- [ ] 正常流程没有冗余日志
- [ ] 日志级别使用正确（ERROR/WARN/INFO/DEBUG）

## 七、示例对比

### ❌ 错误示例（日志冗余且无价值）

```python
async def create_order(user_id, items):
    logger.debug(f"进入create_order方法")
    logger.debug(f"user_id={user_id}, items={items}")
    
    logger.debug("开始验证用户")
    user = await get_user(user_id)
    logger.debug(f"获取到用户: {user}")
    
    logger.debug("开始检查库存")
    for item in items:
        logger.debug(f"检查item {item.id}的库存")
        stock = await check_stock(item.id)
        logger.debug(f"item {item.id}库存={stock}")
        if stock < item.quantity:
            logger.debug(f"库存不足: {stock} < {item.quantity}")
            raise StockError(f"库存不足")
    
    logger.debug("开始创建订单")
    order = Order(user_id=user_id, items=items)
    await order.save()
    logger.debug(f"订单创建成功: {order.id}")
    
    logger.debug("离开create_order方法")
    return order
```

### ✅ 正确示例（精简且有用）

```python
async def create_order(user_id, items):
    try:
        user = await get_user(user_id)
        if not user or user.status != "active":
            logger.warning("用户无效，无法创建订单", extra={
                "user_id": user_id,
                "reason": "用户不存在或已禁用"
            })
            raise UserInvalidError("用户无效")
        
        # 批量检查库存，只记录汇总
        stock_result = await batch_check_stock([item.id for item in items])
        insufficient = [
            {"id": item.id, "required": item.quantity, "available": stock_result[item.id]}
            for item, stock_result in zip(items, stock_result)
            if stock_result < item.quantity
        ]
        
        if insufficient:
            logger.warning("库存不足", extra={
                "user_id": user_id,
                "insufficient_items": insufficient,
                "trace_id": request.state.trace_id
            })
            raise StockError("库存不足")
        
        order = Order(user_id=user_id, items=items)
        await order.save()
        
        logger.info("订单创建成功", extra={
            "order_id": order.id,
            "user_id": user_id,
            "item_count": len(items),
            "trace_id": request.state.trace_id
        })
        
        return order
        
    except Exception as e:
        logger.error("订单创建失败", extra={
            "user_id": user_id,
            "items": [{"id": i.id, "quantity": i.quantity} for i in items],
            "error": str(e),
            "error_type": type(e).__name__,
            "trace_id": request.state.trace_id
        })
        raise
```

## 八、总结

### 🎯 核心原则

1. **异常必记**：所有错误、异常、失败必须有ERROR日志
2. **上下文完整**：错误日志必须包含足够的排查信息
3. **链路可追**：所有日志必须包含trace_id
4. **正常从简**：正常流程不要每一步都记录
5. **敏感不露**：密码、密钥、个人信息必须脱敏

### 📏 日志密度参考

| 场景 | 每请求日志数 |
|------|-------------|
| 正常请求 | 1-3条（关键业务事件） |
| 参数校验失败 | 1条WARN |
| 业务逻辑失败 | 1条ERROR |
| 外部调用失败 | 1条ERROR + 重试WARN |
| 系统异常 | 1条ERROR（带堆栈） |
