### 题目

[找出临界点之间的最小和最大距离](https://leetcode.cn/problems/find-the-minimum-and-maximum-number-of-nodes-between-critical-points?envType=daily-question&envId=2026-08-31)

链表中的 **临界点** 定义为一个 **局部极大值点** **或** **局部极小值点 。**

如果当前节点的值 **严格大于** 前一个节点和后一个节点，那么这个节点就是一个  **局部极大值点** 。

如果当前节点的值 **严格小于** 前一个节点和后一个节点，那么这个节点就是一个  **局部极小值点** 。

注意：节点只有在同时存在前一个节点和后一个节点的情况下，才能成为一个 **局部极大值点 / 极小值点** 。

给你一个链表 `head` ，返回一个长度为 2 的数组 `[minDistance, maxDistance]` ，其中 `minDistance` 是任意两个不同临界点之间的最小距离，`maxDistance` 是任意两个不同临界点之间的最大距离。如果临界点少于两个，则返回 `[-1，-1]` 。

### 初代码

```java
public int[] nodesBetweenCriticalPoints(ListNode head) {
    ListNode prev = head;
    ListNode curr = head.next;

    int firstCriticalPoint = -1;
    int lastCriticalPoint = -1;
    int index = 1;
    int min = Integer.MAX_VALUE;

    while (curr != null && curr.next != null) {
        if ((curr.val - prev.val) * (curr.val - curr.next.val) > 0) {
            if (firstCriticalPoint == -1) {
                firstCriticalPoint = index;
            }
            if (lastCriticalPoint != -1) {
                min = Math.min(min, index - lastCriticalPoint);
            }
            lastCriticalPoint = index;
        }
        prev = curr;
        curr = curr.next;
        index++;
    }

    if (min == Integer.MAX_VALUE) {
        return new int[] { -1, -1 };
    }

    return new int[] { min, lastCriticalPoint - firstCriticalPoint };
}
```

问题：在某个输入中，实际值为[1,10123]，预期结果为[1,10124] 

### 代码的核心问题

#### 1. 最可能导致结果偏差的原因：**整数溢出造成临界点漏判**

你用 `(curr.val - prev.val) * (curr.val - curr.next.val) > 0` 判断极值，两个 `int` 差值相乘时，若数值较大，乘积会超出 `int` 的取值范围（-2^31 ~ 2^31-1），发生有符号溢出，导致乘积符号错误，最终漏判/误判临界点。

这正好能解释你遇到的「最小距离正确、最大距离差1」的现象：

- 前面的临界点都正常识别，因此相邻节点的最小距离计算正确；
- 恰好最后一个临界点因溢出被漏判，`lastCriticalPoint` 停在了倒数第二个临界点的位置，导致最大距离少了最后一段差值，整体偏差1。

#### 2. 次要问题：边界鲁棒性不足

虽然题目保证输入合法，但链表长度小于3时（无任何临界点），虽然代码也能返回 `[-1,-1]`，但显式处理边界更严谨，也避免空指针风险。

---

### 修复方案

#### 方案A：直接改写判断逻辑，彻底避免乘法（推荐）

不用乘积判断，直接判断「同时大于两边」或「同时小于两边」，逻辑更直观，完全无溢出风险。

```
public int[] nodesBetweenCriticalPoints(ListNode head) {
    // 少于3个节点不可能存在临界点
    if (head == null || head.next == null || head.next.next == null) {
        return new int[]{-1, -1};
    }

    ListNode prev = head;
    ListNode curr = head.next;
    int firstCritical = -1;
    int lastCritical = -1;
    int minDist = Integer.MAX_VALUE;
    int index = 1; // curr 对应的 0-based 索引

    while (curr.next != null) {
        boolean isLocalMax = curr.val > prev.val && curr.val > curr.next.val;
        boolean isLocalMin = curr.val < prev.val && curr.val < curr.next.val;

        if (isLocalMax || isLocalMin) {
            if (firstCritical == -1) {
                firstCritical = index;
            } else {
                minDist = Math.min(minDist, index - lastCritical);
            }
            lastCritical = index;
        }

        prev = curr;
        curr = curr.next;
        index++;
    }

    // 临界点少于2个
    if (firstCritical == lastCritical) {
        return new int[]{-1, -1};
    }

    return new int[]{minDist, lastCritical - firstCritical};
}
```

#### 方案B：保留乘积写法，转为 long 避免溢出

如果想保留原逻辑，将差值强转为 `long` 再相乘，也能解决溢出问题：

```
long diffPrev = (long) curr.val - prev.val;
long diffNext = (long) curr.val - curr.next.val;
if (diffPrev * diffNext > 0) {
    // 临界点处理
}
```

### 补充验证

原代码在数值较小时逻辑完全正确，比如经典用例 `head = [5,3,1,2,5,1,2]`：

- 临界点对应 0-based 索引：`2, 4, 5`
- 最小距离：`1`（4和5），最大距离：`3`（2和5）
- 原代码和修复后代码都能正确输出 `[1, 3]`

只有当节点数值差较大、乘积溢出int时，才会出现你遇到的偏差。
