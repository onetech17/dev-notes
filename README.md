# dev-notes 开发问题知识库

> 个人技术答疑沉淀仓库：把散落在各 AI 对话工具里的问题、排错过程和方案统一归档，可检索、可复盘。
>
> 创建时间：2026-08-29

---

## 一、问题分流原则

提问前先判断问题类型，固定入口，避免同一问题在多个工具间来回切：

| 问题类型 | 去哪问 | 例子 |
|---|---|---|
| 依赖当前代码库上下文 | AI IDE（Qoder / Trae） | 这个函数为什么报错、跨文件重构、这段逻辑什么意思 |
| 通用技术答疑（不依赖本仓库代码） | 固定一个主力对话工具（默认豆包） | 概念解释、命令用法、报错排查、方案选型、环境配置 |
| 需求分析 / 设计文档 / 非编码事务 | 同一个主力对话工具 | 需求拆解、接口设计、写周报 |

其他对话工具仅作为交叉验证，不作为日常入口。

## 二、目录结构

```
dev-notes/
├── README.md              # 本文件：索引与使用规范
├── 01-报错排查/           # 报错、异常、排障类问题
├── 02-概念理解/           # 技术概念、原理、机制类笔记
├── 03-方案选型/           # 技术选型、工具对比、架构决策
├── 04-环境配置/           # 开发环境、工具链、部署配置
├── 05-需求与设计/         # 需求分析、接口/系统设计
├── templates/             # 笔记模板
│   └── 笔记模板.md
├── 周复盘/                # 周复盘笔记（按 ISO 周命名，如 2026-W37.md）
└── archive/               # 过时内容归档（不删除）
```

### 分类判断标准

- **报错排查**：有明确报错信息或异常现象，目标是"让它跑起来"
- **概念理解**：没有报错，目标是"搞懂它是什么/为什么"
- **方案选型**：面临多个选项，目标是"决定用哪个"，需记录决策依据
- **环境配置**：安装、配置、版本、权限相关，步骤可复现
- **需求与设计**：业务需求拆解、技术方案设计文档

## 三、文件命名规范

固定格式：`YYYY-MM-DD-技术栈-关键词.md`

- 日期：问题解决当天
- 技术栈：小写，如 linux / git / java / node / windows / logging
- 关键词：简短描述，用中文或英文均可，多个词用连字符 `-` 连接

示例：
- `2026-09-01-java-每日一题-int溢出.md`
- `2026-09-03-logging-后端日志规范.md`

## 四、使用流程

### 每日（约 5 分钟）

1. 有价值的对话当天按 `templates/笔记模板.md` 存档，不值得留的直接放弃
2. 文件放入对应分类目录，按命名规范命名
3. 在本 README 的「笔记索引」表登记一行
4. `git add . && git commit -m "notes: 关键词"`

### 每周五（约 10 分钟）

让 AI 读取本周新增笔记，生成周复盘。提示词：

```
读取 dev-notes 仓库本周新增的全部笔记，完成：
1. 按问题类型归类（报错排查/概念理解/方案选型/环境配置/需求设计）
2. 提炼共性根因（哪些问题本质上是同一个知识点）
3. 列出本周踩坑 Top3 及规避方法
4. 列出待深入学习的知识点
输出为 Markdown 周复盘。
```

### 每月末（约 20 分钟）

1. 按标签统计高频问题，反复出现的类别 = 知识盲区，安排系统学习
2. 过时/失效的笔记移入 `archive/`（保留不删除）
3. 更新索引表

## 五、标签规范

每篇笔记头部写 `标签`，小写，逗号分隔，便于 grep：

- 技术栈标签：`linux`, `windows`, `git`, `java`, `leetcode`, `node`, `npm`, `npx`, `electron`, `appimage`, `tar`, `zip`, `proxy`, `socks5`, `logging`, `scala`, `sbt`, `sql`, `postgres`, `docker`, `k8s`, `idea`, `jdk`
- 类型标签：`排错`, `概念`, `选型`, `配置`, `设计`
- 状态标签（可选）：`待验证`, `已解决`, `有坑`

检索示例：

```bash
# 找所有 sbt 相关笔记
grep -rl "sbt" --include="*.md" .

# 找所有未解决的问题
grep -rl "待验证" --include="*.md" .
```
