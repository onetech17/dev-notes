Git 忽略文件主要靠 **`.gitignore` 文件**，下面按场景说明。

## 一、基本用法：创建 .gitignore

在仓库根目录（或任意子目录）新建 `.gitignore` 文件，每行写一条忽略规则：

```gitignore
# 忽略单个文件
secret.txt

# 忽略整个文件夹（末尾 / 表示目录）
node_modules/
dist/
build/

# 忽略所有 .log 文件
*.log

# 但保留某个文件（! 表示取反/例外）
*.log
!important.log
```

> 以 `#` 开头是注释；空行不生效。

## 二、规则语法速查

| 写法 | 含义 |
|---|---|
| `foo.txt` | 忽略任意目录下名为 foo.txt 的文件 |
| `/foo.txt` | 只忽略**根目录**下的 foo.txt |
| `build/` | 忽略所有名为 build 的文件夹 |
| `doc/*.md` | 忽略 doc 目录下一层的 .md |
| `doc/**/*.pdf` | 忽略 doc 下**所有层级**的 .pdf |
| `*.tmp` | `*` 匹配任意字符 |
| `file?.log` | `?` 匹配单个字符 |
| `!keep.log` | `!` 取消忽略（强制保留） |

## 三、关键坑：已经被 Git 跟踪的文件，光写 .gitignore 无效

`.gitignore` 只对**未跟踪**的文件生效。如果文件之前已经 `git add`/提交过，需要先从索引移除（保留本地文件）：

```bash
# 移除单个文件的跟踪，但本地文件还在
git rm --cached config.ini

# 移除整个文件夹的跟踪
git rm -r --cached node_modules

# 然后提交
git commit -m "stop tracking ignored files"
```

之后 `.gitignore` 里的规则才会对它们生效。

## 四、几种进阶方式

**1. 只在自己本地忽略，不影响团队（不提交规则）**

编辑仓库里的 `.git/info/exclude`，语法和 `.gitignore` 一样，但不会被提交：

```bash
# .git/info/exclude
my-local-test.txt
.vscode/
```

**2. 全局忽略（对你所有仓库生效）**

```bash
# 配置全局忽略文件
git config --global core.excludesfile ~/.gitignore_global
```

然后在 `~/.gitignore_global` 里写通用规则，例如：

```gitignore
.DS_Store
Thumbs.db
.idea/
.vscode/
*.swp
```

**3. 临时忽略已跟踪文件的改动（本地调试用）**

```bash
git update-index --assume-unchanged config.ini   # 暂时忽略改动
git update-index --no-assume-unchanged config.ini # 恢复跟踪
```

## 五、排查规则是否生效

```bash
# 查看某个文件为什么被忽略/命中了哪条规则
git check-ignore -v node_modules/xxx.js
```

输出会显示命中的 `.gitignore` 路径和行号，方便定位。

---

**最常用的一套流程**：根目录建 `.gitignore` 写规则 → 已跟踪的文件用 `git rm --cached` 移除索引 → 提交。需要一份各语言通用模板可以参考 GitHub 官方仓库 [github/gitignore]([https://github.com/github/gitignore](https://github.com/github/gitignore))。
