## 1. npx 是什么

### 定义

**npx** = **N**ode **P**ackage e**X**ecute

是 npm 5.2+ 版本开始自带的**包执行工具**，用于临时运行 npm 包中的可执行命令。

### 核心特点

| 特点 | 说明 |
|------|------|
| **临时执行** | 不需要全局安装包，用完即走 |
| **自动下载** | 本地没有时自动下载到缓存 |
| **不污染全局** | 不会把命令安装到系统 PATH |
| **版本灵活** | 可以指定特定版本执行 |

### 基本语法

```bash
# 执行本地 node_modules/.bin 中的命令
npx <command>

# 临时下载并执行某个包的命令
npx <package-name>

# 指定版本执行
npx <package-name>@<version>

# 执行包的子命令
npx <package-name> <subcommand>
```

## 2. npx 的工作原理

### 执行流程

```
┌─────────────────────────────────────────────────────────────┐
│                    npx @deepseek-ai/dsh web                  │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤1: 检查本地是否有 @deepseek-ai/dsh                      │
│  ├─ 有 → 直接使用本地版本                                    │
│  └─ 没有 → 进入步骤2                                         │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤2: 临时下载到 npm 缓存目录                               │
│  ~/.npm/_npx/<hash>/node_modules/@deepseek-ai/dsh           │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤3: 执行包的 bin 脚本，传入参数 "web"                     │
│  node <cache-dir>/node_modules/.bin/dsh web                 │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤4: 启动 DeepSeek Harness Web 服务器                      │
│  http://127.0.0.1:3080/                                     │
└─────────────────────────────────────────────────────────────┘
```

### 缓存位置

```bash
# npx 临时缓存目录
~/.npm/_npx/

# 查看缓存内容
ls -la ~/.npm/_npx/
```

## 3. npx vs npm install -g

### 对比表

| 方面 | `npx <package>` | `npm install -g <package>` |
|------|-----------------|---------------------------|
| **安装位置** | 临时缓存目录 | 全局 node_modules |
| **命令可用性** | 仅 npx 执行时可用 | 全局 PATH 可用 |
| **磁盘占用** | 临时，可清理 | 永久占用 |
| **版本管理** | 每次可指定不同版本 | 固定安装的版本 |
| **适用场景** | 一次性/偶尔使用 | 频繁使用的工具 |

### 实际对比

```bash
# ─────────────────────────────────────────────────────────────
# 方式1: 使用 npx（临时执行）
# ─────────────────────────────────────────────────────────────
npx @deepseek-ai/dsh web
# ✅ 可以启动 DeepSeek Harness
# ❌ 但 dsh 命令不在全局 PATH 中

dsh --version
# ❌ bash: dsh: 未找到命令


# ─────────────────────────────────────────────────────────────
# 方式2: 全局安装（永久可用）
# ─────────────────────────────────────────────────────────────
npm install -g @deepseek-ai/dsh
# ✅ dsh 命令安装到全局 PATH

dsh web
# ✅ 可以直接运行
# ✅ dsh plugin 等子命令也可用
```

## 4. 实战案例：DeepSeek Harness

### 4.1 背景

DeepSeek Harness 是 DeepSeek 推出的 AI Agent 开发框架，采用"一切皆插件"的架构。

- **官方仓库**: https://github.com/deepseek-ai/deepseek-harness
- **npm 包名**: `@deepseek-ai/dsh`
- **可执行命令**: `dsh`

### 4.2 典型使用场景

#### 场景1: 快速体验（推荐 npx）

```bash
# 第一次使用，不想全局安装
npx @deepseek-ai/dsh web

# 输出:
# Starting DeepSeek Harness development server...
# Ready on http://127.0.0.1:3080/
```

**优点**:
- 无需安装
- 不占用全局空间
- 随时可以清理

**缺点**:
- 每次都要打 `npx @deepseek-ai/dsh`
- 子命令如 `dsh plugin` 无法直接使用

---

#### 场景2: 日常开发（推荐全局安装）

```bash
# 全局安装
npm install -g @deepseek-ai/dsh

# 验证安装
dsh --version

# 启动 Web 界面
dsh web

# 安装插件（新终端）
dsh plugin --profile web add dsh-better-sidebar

# 查看已安装插件
dsh plugin --profile web list
```

**优点**:
- 命令简短
- 所有子命令可用
- 适合频繁使用

**缺点**:
- 占用全局空间
- 需要管理版本更新

---

#### 场景3: 指定版本测试

```bash
# 使用特定版本（不干扰全局安装）
npx @deepseek-ai/dsh@0.1.0 web
npx @deepseek-ai/dsh@latest web
```

---

### 4.3 遇到的问题与解决

#### 问题1: `bash: dsh: 未找到命令`

**现象**:
```bash
npx @deepseek-ai/dsh web
# ✅ 可以启动

dsh plugin --profile web add dsh-better-sidebar
# ❌ bash: dsh: 未找到命令
```

**原因**: `npx` 只是临时执行，不会把 `dsh` 命令安装到全局 PATH。

**解决方案**:

| 方案 | 命令 | 适用场景 |
|------|------|---------|
| 全局安装 | `npm install -g @deepseek-ai/dsh` | 频繁使用 |
| 继续用 npx | `npx @deepseek-ai/dsh plugin ...` | 偶尔使用 |
| Web界面安装 | 浏览器访问 http://127.0.0.1:3080/ | 图形化操作 |

---

#### 问题2: 需要 pnpm 但找不到

**现象**:
```bash
npx @deepseek-ai/dsh plugin --profile web add dsh-better-sidebar
# dsh: pnpm not found on PATH — install pnpm to manage profile plugins
```

**原因**: DeepSeek Harness 使用 `pnpm` 管理插件依赖，但 pnpm 未安装。

**解决方案**:
```bash
# 全局安装 pnpm
npm install -g pnpm

# 或使用 corepack (Node.js 16.13+)
corepack enable pnpm
```

---

#### 问题3: 企业环境只读文件系统

**现象**:
```bash
npm error code EROFS
npm error rofs EROFS: read-only file system, open '/home/user/.npm/_cacache/tmp/***'
```

**原因**: 公司/容器环境限制了用户目录的写入权限。

**解决方案**:
```bash
# 使用临时目录作为缓存
npm config set cache /tmp/npm-cache
npm config set prefix /tmp/npm-global

# 或使用自定义配置文件
echo -e "cache=/tmp/npm-cache\nprefix=/tmp/npm-global" > /tmp/npmrc
npm install -g pnpm --userconfig=/tmp/npmrc
```

## 5. 常见问题与解决方案

### Q1: npx 每次都要下载吗？

**答**: 不是。npx 会缓存到 `~/.npm/_npx/`，再次执行相同包时会使用缓存。

```bash
# 第一次执行（下载）
npx @deepseek-ai/dsh web

# 第二次执行（使用缓存）
npx @deepseek-ai/dsh web
```

---

### Q2: 如何清理 npx 缓存？

```bash
# 清理 npx 缓存
rm -rf ~/.npm/_npx/

# 或使用 npm 命令
npm cache clean --force
```

---

### Q3: npx 可以执行本地安装的包吗？

**答**: 可以。npx 优先使用本地 `node_modules/.bin/` 中的命令。

```bash
# 项目本地安装
npm install @deepseek-ai/dsh

# 执行本地版本
npx dsh web
```

---

### Q4: 如何指定 npx 使用的 Node 版本？

```bash
# 使用特定 Node 版本执行（需要 nvm）
nvm exec 18 npx @deepseek-ai/dsh web
```

---

### Q5: npx 与 yarn dlx / pnpm dlx 有什么区别？

| 工具 | 命令 | 说明 |
|------|------|------|
| npm/npx | `npx <package>` | npm 自带 |
| yarn | `yarn dlx <package>` | Yarn 的等价命令 |
| pnpm | `pnpm dlx <package>` | pnpm 的等价命令 |

功能基本相同，只是不同包管理器的实现。

## 6. 最佳实践

### ✅ 推荐做法

```bash
# 1. 快速体验新工具 → 使用 npx
npx @deepseek-ai/dsh web

# 2. 频繁使用的工具 → 全局安装
npm install -g @deepseek-ai/dsh

# 3. 测试特定版本 → 指定版本号
npx @deepseek-ai/dsh@0.1.0 web

# 4. 企业内网 → 配置镜像源
npm config set registry https://registry.npmmirror.com

# 5. 需要代理 → 配置代理
npm config set proxy http://127.0.0.1:7890
npm config set https-proxy http://127.0.0.1:7890
```

---

### ❌ 避免的做法

```bash
# 1. 不要混用 npx 和全局命令
npx @deepseek-ai/dsh web
dsh plugin add xxx  # ❌ 会报错，应该用 npx 前缀

# 2. 不要在只读环境尝试全局安装
# 先检查目录权限
ls -la ~/.npm/

# 3. 不要忘记安装依赖工具
# DeepSeek Harness 需要 pnpm
npm install -g pnpm  # 先安装这个
```

---

### 📋 完整工作流示例

```bash
# ============================================
# 步骤1: 配置环境（首次设置）
# ============================================

# 设置国内镜像源（中国大陆用户）
npm config set registry https://registry.npmmirror.com

# 安装 pnpm（DeepSeek Harness 依赖）
npm install -g pnpm

# 安装 dsh 全局命令
npm install -g @deepseek-ai/dsh

# 验证
dsh --version
pnpm --version


# ============================================
# 步骤2: 启动 DeepSeek Harness
# ============================================
dsh web
# 访问 http://127.0.0.1:3080/


# ============================================
# 步骤3: 安装插件（新终端窗口）
# ============================================
dsh plugin --profile web add dsh-better-sidebar
dsh plugin --profile web add dsh-theme-dark


# ============================================
# 步骤4: 管理插件
# ============================================
dsh plugin --profile web list          # 查看已安装
dsh plugin --profile web remove xxx    # 卸载插件
dsh plugin --profile web update        # 更新所有插件


# ============================================
# 步骤5: 清理（可选）
# ============================================
npm cache clean --force
pnpm store prune
```
