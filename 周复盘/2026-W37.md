## 二、共性根因

三篇分属不同工具，但本质是同一个知识方向：**"东西放在哪、怎么被找到"——文件与命令的查找规则**：

- .gitignore：规则如何匹配路径、为什么已跟踪文件免疫忽略规则（索引 vs 工作区的区别）；
- npx：命令解析顺序（本地 `node_modules/.bin` → 临时缓存 → 全局 PATH），所以 npx 跑完后裸命令不存在；
- Windows：程序与数据分别落在哪个目录（Program Files / AppData / ProgramData），`%变量%`/`shell:`/`.msc` 各管一层入口。

核心一句话：**配置类知识的本质不是记命令，而是记"分层与查找"的规则**——分层懂了，命令可以现查。

## 三、本周易错点 Top3（源自笔记，非实际踩坑记录）

> 本周无报错排查类记录，以下为三篇主题最容易出错的点及规避方法。

| # | 易错点 | 后果 | 规避方法 |
|---|---|---|---|
| 1 | **已跟踪的文件只往 .gitignore 加规则** | 改动照样被提交，误以为已忽略 | 先 `git rm --cached <file>` 再提交；用 `git check-ignore -v` 验证规则命中 |
| 2 | **npx 执行完直接敲裸命令**（如 `dsh plugin ...`） | `command not found`：npx 不写入 PATH | 偶尔用就带 `npx` 前缀，频繁使用 `npm install -g`；注意 dsh 要求 Node ^22.19 或 >=24 |
| 3 | **Windows 目录直觉错误**：以为 System32 放 32 位、忽略隐藏的 ProgramData | 找错 DLL；漏查服务端软件的数据目录 | 记住反直觉点：System32=64 位、SysWOW64=32 位；排查服务软件先翻 ProgramData |
