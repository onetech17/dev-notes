## 二、共性根因

本周只有 1 篇，严格意义上无"本周内共性"。放到近三周脉络（09-09 npx → 09-12 Windows 目录与指令 → 09-20 压缩包）看，三篇本质是**同一个知识方向：操作系统原语与命令行工具链的工作机制**，且都体现同一种学习模式——**不只记命令，还记"为什么是这条命令"**：

- npx：理解"临时下载执行包"的机制，而非死记命令；
- Windows 目录：理解 `AppData/ProgramData` 分工与 `%变量%/shell:` 的分层；
- 压缩包：理解 **ZIP 的中央目录（随机访问，列目录快）vs tar 系的流式结构（必须全量扫描）**，命令差异（`-z`/`-J`、`-p`/`-O`）只是底层差异的表象。

核心知识点一句话：**归档格式是否带"目录索引"，决定了列文件列表是秒开还是全量扫描。**

## 三、本周易错点 Top3（源自笔记，非实际踩坑记录）

> 本周无报错排查类记录，以下为该主题最容易出错的三个点及规避方法。

| # | 易错点 | 后果 | 规避方法 |
|---|---|---|---|
| 1 | **tar 参数大小写混淆**：gzip 用小写 `-z`，xz 用大写 `-J` | `tar -tzf x.tar.xz` 报错或乱码 | 记口诀：z=g**z**ip（小写），J 对应 xz；操作前先 `file 压缩包` 确认真实格式 |
| 2 | **以为 tar.gz 列列表和 zip 一样快**，对几十 GB 包直接 `tar -tzf` | 终端卡死/长时间高 CPU（xz 更明显） | 先 `head -n 20` 限量，或管道接 `less`；需要随机访问大归档时优先 zip/7z |
| 3 | **在 Windows 上找 `unzip` 命令** | 命令不存在（系统自带的是 bsdtar） | 用 WSL / Git Bash，或 `7z l 包名`；Win10/11 自带 `tar` 可查 tar.gz |

## 四、待深入学习知识点

1. **压缩与归档的分层本质**：归档（tar，不压缩）与压缩（gzip/xz/bzip2/zstd）为什么分离；`zstd` 与 xz/gzip 的速度-压缩率取舍（tar.zst 是现代发行版打包新趋势）。
2. **归档格式的索引结构**：ZIP Central Directory、tar 的顺序结构、7z/RAR 的头设计；延伸理解"流式处理 vs 随机访问"的通用权衡（与日志、消息队列同构）。
3. **管道与流式工具链**：`-O` 输出到 stdout 后接 `grep/sed` 直接处理包内文件、进程替换 `<(...)`、CRC 校验。
4. **大文件运维实操**：分卷压缩、损坏归档恢复、多核压缩（`pigz`、`xz -T0`、`zstd -T0`）。
