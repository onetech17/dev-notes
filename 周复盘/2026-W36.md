## 二、共性根因

1. **Linux 桌面应用分发（AppImage + Electron 同属一个知识域）**
   AppImage 是「分发格式」，Electron 是「开发框架」，落地交汇点是用 `electron-builder` 打包 Electron 应用成
   AppImage，本质都是「一套代码/包如何在多 Linux 发行版便携分发」。

2. **对底层机制理解不够精确导致误判（横跨 3 篇）**
    - int 溢出：不了解 `int` 取值范围，用乘法判符号触发有符号溢出 → 结果差 1；
    - GitHub 代理：混淆「HTTPS 代理」≠「代理服务器本身用 HTTPS」，实际是 HTTP 代理不支持 HTTPS CONNECT 隧道；
    - 日志规范：对「在哪打、打多少」没有尺度感，导致日志爆炸或漏掉关键上下文。
      三点表面不同，根因是同一个元问题： **以「想当然」代替对数值边界 / 协议机制 / 规范的精确理解**。

## 三、本周踩坑 Top3

| # | 坑 | 根因 | 规避方法 |
|---|---|---|---|
| 1 | **int 乘法判极值溢出**，最大距离偏差 1    | 两个 int 差值相乘超出 `-2^31 ~ 2^31-1`，有符号溢出导致临界点漏判 | 弃用乘法，改写 `a>b && a>c \|\| a<b && a<c`；或差值强转 `long` 再乘 |
| 2 | **`git push` 报 `Proxy CONNECT aborted`** | HTTP 代理（80 端口）不支持 HTTPS CONNECT 隧道，SSH 22 被墙       | `https_proxy`/`ALL_PROXY` 用 `socks5://proxysz.zte.com.cn:1080`     |
| 3 | **日志冗余 + 敏感信息泄露**               | 每个函数出入口、循环内部都打日志；明文打印密码/密钥/身份证       | 只记异常与关键业务事件，结构化 JSON + trace_id，敏感字段脱敏        |

## 四、待深入学习知识点

1. **整数溢出与数值安全**：补码、有符号/无符号溢出、`BigInteger`、数值比较的安全写法，及同类题通解。
2. **Linux 应用打包生态**：AppImage / Snap / Flatpak 三者的本质区别、优劣与选型；`electron-builder` 完整打包流程。
3. **Electron 安全与优化**：主/渲染进程 IPC 与 `contextIsolation`、体积/内存/启动速度优化，以及与 **Tauri** 的对比。
4. **网络代理体系**：HTTP CONNECT 隧道原理、SOCKS4/5、正向/反向代理、`no_proxy` 规则写法、TLS 代理的区别。
5. **可观测性**：结构化日志落地方案（trace/span 透传）、`OpenTelemetry`、日志采样与脱敏策略。
