# 笔记模板集合

> 使用方法：复制对应模板到分类目录，按命名规范重命名后填写。
> 文件名格式：`YYYY-MM-DD-技术栈-关键词.md`
> 不需要的字段可以删，但「问题现象、根因、解决方案」是核心，必须保留。

---

## 模板一：报错排查（最常用）

```markdown
# 一句话问题标题

- 日期：YYYY-MM-DD
- 标签：技术栈, 排错
- 环境：操作系统 / 软件版本 / JDK 版本等
- 状态：已解决 / 待验证 / 有坑

## 问题现象
（报错原文完整粘贴，包括堆栈关键行；描述触发场景：做了什么操作后出现）

## 排查过程
1. 第一步检查了什么，排除了什么
2. 第二步定位到哪里

## 根因
（一句话说清本质原因，避免只记"怎么修"不记"为什么"）

## 解决方案
（可直接复制的命令 / 配置 / 代码，标注每步作用）

## 关联知识
- 延伸概念：
- 官方文档：
- 相似问题区分：

## 原文对话
（AI 对话分享链接 / 截图位置）
```

## 模板二：概念理解

```markdown
# 概念名称

- 日期：YYYY-MM-DD
- 标签：技术栈, 概念
- 关联笔记：[[]]（Obsidian 双链，或写相对路径）

## 一句话解释
（用自己的话概括，不照抄定义）

## 核心机制
（它是怎么工作的，配合流程图/时序图/表格说明）

## 关键细节
1. 容易混淆的点
2. 边界条件 / 适用范围

## 代码或示例
（最小可运行示例）

## 类比记忆
（用熟悉的事物类比，辅助记忆）

## 原文对话
（链接 / 截图）
```

## 模板三：方案选型

```markdown
# 选型主题：X 场景选 A 还是 B

- 日期：YYYY-MM-DD
- 标签：技术栈, 选型
- 决策状态：已决定 / 待定 / 已推翻

## 需求背景
（业务场景、约束条件：预算、性能、团队熟悉度、维护成本）

## 候选方案对比

| 维度 | 方案 A | 方案 B | 方案 C |
|---|---|---|---|
| 核心优势 | | | |
| 主要劣势 | | | |
| 成本 | | | |
| 生态/社区 | | | |
| 与现有系统兼容性 | | | |

## 最终决策
（选了哪个）

## 决策依据
（为什么选它，关键决定因素是什么；放弃其他方案的理由）

## 风险与后续验证点
（这个选择可能带来什么风险，什么情况下需要重新评估）

## 原文对话
（链接 / 截图）
```

## 模板四：环境配置

```markdown
# 配置主题：在什么环境装什么

- 日期：YYYY-MM-DD
- 标签：技术栈, 配置
- 环境：操作系统版本 / 硬件 / 网络环境

## 目标
（配置完成后要达到的可验证状态）

## 前置条件
（需要先装好什么、账号权限要求）

## 配置步骤
### 1. 步骤一
（命令 + 预期输出）

### 2. 步骤二

## 验证方式
（执行什么命令/访问什么地址，看到什么结果算成功）

## 踩坑记录
（过程中遇到的报错及处理，这是这类笔记最有价值的部分）

## 回滚方式
（如何卸载/还原，防止配坏无法恢复）

## 原文对话
（链接 / 截图）
```
